How one action travels through Refrain

You explain what you just studied in two or three sentences, and the coach marks the phrases that really are yours. This map follows that one action from the button you press to the highlighter on the page.

Written against commit 15f1b27 (Record the deploy of the final-walk fix), Oct 4, 2026 Reference route: read from the finished code, not walked hands-on

What is in the app

Five pieces make up the app.

  • The pages

    static/ · Plain HTML, CSS and JavaScript modules with no build step. One file per screen in static/js/screens/.

  • The server

    refrain/ · A small Flask app. It serves the pages and answers three JSON requests: /api/roadmap, /api/check and /api/debrief.

  • The fixed rules

    refrain/rules.py · Plain Python for what the AI must not decide: when a stage moves, how many distractions a session allows, the default roadmap, and which quotes are real.

  • The coach

    Gemini 3.8 Flash on Vertex AI · Writes only the words. Each request is one call that must answer in a JSON schema (refrain/schemas.py) and is checked in refrain/coach.py.

  • Saved progress

    static/js/store.js · One JSON value in the browser's localStorage under the key refrain.v1. The server stores nothing.

One action, start to finish

You press Get feedback on the teach-back screen. Five steps later your explanation is back on the page with your own words marked.

Stop 2 · The server asks the coach, then checks the answer (steps 2–4)

Follow it through refrain/routes.py → debrief(), then refrain/coach.py → write_debrief(), then refrain/rules.py → verbatim_quotes().

First debrief() checks the input and lets the fixed rules decide the roadmap change, so that answer exists even if the coach cannot respond. Then write_debrief() builds the prompt and asks Gemini for JSON that includes got_quotes: short phrases it says it copied from your explanation. Then comes the check that matters. verbatim_quotes() keeps a phrase only if it really appears in what you wrote (ignoring case and quotation marks) and returns your own characters, not the coach's. If the coach invented a phrase, the request gets one retry; after that the invented phrase is dropped.

Show the code: verbatim_quotes() is the check 
def verbatim_quotes(quotes, explanation, limit=3):
    """(kept, dropped): the phrases that really are in the explanation, as the explanation writes them.

    Matching ignores case and the quotation marks or end punctuation the coach may add, and each kept
    phrase is the explanation's own text, so the browser can mark exactly those characters.
    """
    kept, dropped, lowered = [], 0, explanation.lower()
    for quote in quotes if isinstance(quotes, list) else []:
        phrase = quote.strip(_QUOTE_EDGES) if isinstance(quote, str) else ""
        if len(phrase) < 3:
            continue
        at = lowered.find(phrase.lower()) if len(lowered) == len(explanation) else explanation.find(phrase)
        if at < 0:
            dropped += 1
            continue
        exact = explanation[at:at + len(phrase)]
        if exact not in kept and len(kept) < limit:
            kept.append(exact)
    return kept, dropped

Stop 3 · Your words come back marked (step 5)

Finish in static/js/progress.js → markSegments(), static/js/screens/debrief.js → marked() and wordsCard(), and static/css/styles.css → .got-mark.

The answer arrives with coach.gotQuotes. markSegments() cuts your text into pieces and flags each place a quote appears. marked() turns only the flagged pieces into <mark> elements; every piece goes in as plain text, so nothing you typed can run as code. The CSS then sweeps the highlighter across each mark. Afterwards fetchDebrief() saves the new rule and warm-up questions with store.update(). The marks are drawn from the response and are not saved.

A practice to reuse: let code check what the AI returns before the screen trusts it

What was decided
The coach may only mark phrases that really appear in the user's own explanation. The AI proposes them; verbatim_quotes() decides. A phrase that is not found is never shown, and the user's own characters are what get marked.
Evidence in the project
Tests cover the rule itself (tests/test_rules.py, test_verbatim_quotes_…) and the whole request (tests/test_api.py, test_quotes_that_are_not_their_words_are_retried_once_then_dropped). Then it was measured with the real model: five scripted debriefs each came back with two or three quotes that were all the user's own text, so none needed a retry and none was dropped (devpost/checklist.md → Revisions → Slice 9).
Use it again
Whenever AI output is shown as fact (a citation, a name, a figure, a quoted sentence), write the smallest rule that code can verify (an exact match, a value in range, an item from an allowed list). Test it with a wrong answer on purpose, then run the real model a few times and count how often the rule had to step in. The tests tell you it works; the count tells you whether it is doing anything.
